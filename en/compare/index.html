A script

A script reads the CSV and runs an INSERT. The next day the file has one row less and the script deletes, or it leaves the record and nobody knows the source no longer has it. There is no preview. There is no hash, so it rewrites even what did not change.

If the salesperson's note sits in the same table, the script clears it when the cell arrives empty. It has no field owner.

A query on the tables

Writing on Espo tables skips the checks, the teams, the history, and the hooks. The day Espo changes a schema, the query is the first piece that breaks, and it breaks quietly.

Nesso talks to Espo only over HTTP. The key, the team, and the close go through the API. The Espo database is not a channel.

A second CRM

Keeping the masters in another product and then chasing them in Espo doubles the truth. Nesso is not that second place. It always has Espo on one side. The other side is a channel: a file, a SELECT, a call.

The recipes for accounts, contacts, sites, and the price list are a mapping to review. They are not a certified connector and they do not replace the ERP.
