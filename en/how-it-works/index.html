Why the run is short

The person who configures does not write a stored procedure and does not open the CRM tables. They choose the channel, the sheet, and the mapping. From there the same engine moves records, whatever the sheet is.

A site webhook can feed Leads and, with a second integration, Contacts. An integration has one connection. If the connection is HTTP, the integration leaves Espo. In the other cases it enters.

Inbound

The external system delivers a row: a call, a SELECT, a file. The key is the integration id plus the external value. On standard sheets the field is cExternalKey. On sheets created by Nesso it is externalKey.

If the row hash is already the one stored, Espo is not called: the row is unchanged. If the key already exists, it is an update. If it does not, it is a create. An identical second send does not duplicate.

Outbound

The cursor remembers the last modifiedAt and the Espo id. The run reads pages of 50 and sends only the mapped fields. The HTTP cursor advances only after the POSTs succeed. If the external key is missing, the pull stops: later records do not leave.

They are two different memories. The hash is the inbound memory. The cursor is the outbound memory. A second run, if nobody in Espo touched those records, exports zero.
