Three pieces

The external system delivers or receives rows: a file, a SELECT, a call, an HTTP endpoint. Nesso holds the connection and the integration. Espo holds the sheets, the teams, the history.

An integration has one connection. A connection can have several integrations. If the connection is HTTP, the integration leaves Espo. In the other cases it enters.

Where the data sits

The sheets sit in Espo. The engine keeps its own memory in a SQLite file: connections, integrations, hash, cursor, journal. That file is not a second CRM and it does not replace Espo.

Without NESSO_SECRET_KEY the passwords in that volume stay cleartext. With the variable, a new save is sealed. The trial does not set the variable.

What does not cross the boundary

No SQL on Espo tables. No production dump in the trial Espo. The Advanced Pack is not in the repository. CRM mail does not pass through the engine. Espo users are not created from a master.

Two different integrations can run together. The same one does not start twice. After an error the full interval is waited, unless retry_failed is on.
