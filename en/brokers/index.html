The ones that run

Inbound: webhook, a SELECT on the external database, CSV, Excel, SFTP, FTPS, PDF, document. Outbound: HTTP, with the cursor. Direction follows the channel. An HTTP integration does not become a load.

The external database is read. Its tables are not written from here, until write-back is on, and even then only the named columns.

The ones that exist and stay off

Write-back, retry queue, portal filter, secret seal: the code is there, the default switch is off. Turning them on is a choice of whoever installs, not a behavior of the trial.

The trial does not set NESSO_SECRET_KEY, does not turn the queue on, does not turn the portal on, does not turn write-back on.

What does not pass through here

CRM mail stays in Espo. The Advanced Pack is not rewritten. Espo users are not created from a master. There is no bridge without Espo on one side. A production dump is not imported.
