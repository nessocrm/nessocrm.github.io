How it enters

The key is the integration id plus the external value. If that key is already on Espo, the run updates. If it is not, it creates. If the hash is identical, it does not call Espo.

A record created by Nesso carries the team. Visibility is a rule: this row belongs to the Sales team, assigned to this person. It is not a permission invented outside Espo.

How it leaves the source

If the row is no longer in the file, the record on Espo is closed. The history stays. The first time a run would close records, it asks for confirmation: a whole list is not closed because of a truncated file, without someone seeing it.

Closing does not delete. It is not the forget function. A closed record can be reopened if the row comes back.

How it goes back

Write-back stays off until it is turned on. Once on, it writes only the named columns. It does not rewrite the whole file and it does not invent columns.

The outbound cursor is not this write. The cursor sends the mapped fields to an HTTP endpoint. Write-back writes on the source the row came from.
