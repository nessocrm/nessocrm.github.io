Espo on one side

There is no run without Espo. The other side is a channel. The product does not become a generic bridge between any two systems.

The HTTP API is the only way to write on Espo. The tables are not an interface.

The source is the truth of its fields

By default an empty cell clears the field. It is annoying and it is correct. The exception is explicit: the field owner is Espo, and then the run does not touch that value.

Write-back stays off until someone turns it on, and even then only on the columns they named.

Close, do not delete

A disappeared row closes the record and keeps the history. The first close asks for confirmation. It is not a deletion and it is not a forget.

Users are not created from a master. The portal is not administered from here: the filter, off by default, does not create users and does not change roles.
